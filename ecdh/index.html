Start with a familiar public key

If you know how an elliptic-curve public key is made, you have the prerequisite. A private key is a number d. A public key is a point Q = dG, where G is the public generator and dG means adding together d copies of G. For a refresher, see point addition and scalar multiplication in the ECDSA guide.

ECDSA uses that key relationship to sign and verify messages. ECDH uses it to establish shared key material. Each party starts by creating a key pair, then applies the same multiplication operation again using the other party’s public point as the starting point.

Why both sides reach the same point

Imagine Bob has already counted out b copies of G and bundled them into one point B. Alice adds a copies of that bundle, for a groups of b. Bob makes b groups of a using Alice’s point A. Both have counted the same number of copies of G.

Alice’s calculationaB = a(bG) = (ab)G
Bob’s calculationbA = b(aG) = (ba)G

Point addition lets you regroup the copies of G. The equality ab = ba is ordinary integer multiplication. Each person has only one private scalar, and the received point already embodies the other scalar’s contribution.

Work it by hand

Alice chooses a = 7 and publishes A = 7G = (0, 6). Bob chooses b = 5 and publishes B = 5G = (9, 16). With those points in hand, Alice adds seven copies of B and Bob adds five copies of A.

Alice uses Bob’s point7(9, 16) = (10, 11)
Bob uses Alice’s point5(0, 6) = (10, 11)
See the point additions
  1. Alice doubles B to get 2B = (7, 11), then doubles again to get 4B = (5, 1). She adds 4B + 2B = (13, 10), then adds B to get 7B = (10, 11).
  2. Bob doubles A to get 2A = (9, 1), then doubles again to get 4A = (7, 6). He adds A to get 5A = (10, 11).

Where each modulus belongs

Coordinates use mod p
The point-addition formulas work in the field of size p = 17. For example, doubling B = (9, 16) uses slope (3·9² + 2)/(2·16) ≡ 5 (mod 17). Division here means multiplying by the denominator’s inverse in that field.
Counts of G wrap mod n
Since 19G = 𝒪, every extra 19 copies of G bring you back to the same point. The shared point is 35G = (35 mod 19)G = 16G. This is a check you can make because the example gives you both private scalars.
Try a prediction

Set Alice’s scalar to 1 and keep Bob’s at 5. Where will the shared point land?

Reveal the answer

Alice computes 1B = B and Bob computes 5G = B. The shared point coincides with Bob’s public point at (9, 16). That is one reason a real private scalar must be unpredictable.

What keeps the shared point secret?

A passive observer has G, A, and B. The task of finding (ab)G from those three points is the computational Diffie–Hellman problem. One possible route is to recover a from A = aG, which is the elliptic-curve discrete logarithm problem, and then compute aB. ECDH assumes computing the shared point from public information is infeasible for the chosen group and properly generated keys.

On our toy curve, an observer could try all 18 private scalars and find the one whose public point matches Alice’s. Real curves have vastly larger groups, and real implementations generate private keys with a cryptographically secure random source.

What if someone changes a public point?

A valid point can belong to anyone. If someone can substitute public keys in transit, Alice and Bob can each establish a different secret with that intermediary. In a certificate-authenticated TLS handshake, the server signs the handshake transcript (which includes the exchanged key shares). The client verifies the signature and certificate to bind the exchange to the expected server.

From shared point to session keys

  1. Check the peer’s key share. For the short Weierstrass curves used by TLS, the peer point must have in-range coordinates, lie on the chosen curve, and differ from the identity. Validation rules depend on the group and protocol.
  2. Compute and encode the shared value. For such curves, TLS encodes the shared point’s x-coordinate as fixed-width bytes. With X25519, public shares and the shared output are encoded Montgomery u-coordinates. TLS aborts if the X25519 shared output is all zero.
  3. Derive the keys needed by the protocol. TLS 1.3 feeds the shared value into its HKDF key schedule. The schedule also uses handshake transcript hashes and labels to derive separate traffic secrets and keys for each direction.

For the toy point (10, 11), the field element x = 10 would fit in one byte, 0a in hexadecimal. Encoding preserves the coordinate’s value. It stays within the field of size p and is fed into key derivation as bytes.

In ECDHE, the last letter stands for ephemeral. Each peer generates a fresh key pair for the exchange and discards the private material when it’s no longer needed. With authenticated ephemeral exchange and proper erasure of session secrets, later compromise of a long-term signing key leaves past sessions protected. This is forward secrecy.
