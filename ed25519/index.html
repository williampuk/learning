Chapter 1

From ECDSA to EdDSA

Alice signs a release so Bob can check its exact bytes using a public key he already trusts. Both ECDSA and EdDSA make that possible. The verifier’s calculation changes.

Think back to the ECDSA proof. It uses a permanent public point, a temporary nonce point, and an equation that can be checked with public data. EdDSA keeps that structure. It uses a Schnorr-style equation and includes the compressed nonce point directly in the signature. EdDSA is the family of signature schemes. Ed25519 is the member built on the edwards25519 curve using SHA-512 and the specific rules taught below.

ECDSA on secp256k1

(r, s)

Both components are integers. Verification rebuilds a point and compares its reduced X-coordinate with r.

Ed25519

(R, S)

The wire format stores a compressed point R and an integer S. Verification uses R and compares entire points.

Use the modular arithmetic and point multiplication lessons if inverses or repeated point addition are unfamiliar. Knowing how to sign with ECDSA is optional. One notation change matters here. Uppercase R is a point, lowercase r is EdDSA’s secret nonce scalar, and [j]P means add point P to itself j times.

Check your intuition · What can Bob learn?

A valid signature links the message bytes to the supplied public key. Bob must establish separately that the key belongs to Alice and decide whether the message authorizes an action.

Chapter 2

Learn a new rule for adding points

The verification equation will need point addition. The shape of the curve determines what rule makes that addition work.

In the ECDSA guide you added Weierstrass points with a chord or tangent. Here we use a twisted Edwards equation with the coefficient of x² fixed at −1. We write the other curve coefficient as dcurve so it cannot be confused with the ECDSA private scalar. A valid point is a pair of field residues satisfying this equation.

−x² + y² ≡ 1 + dcurvex²y² (mod p)

Our toy field has prime p = 53 and dcurve = 3. For the base point B = (4, 43), the left side reduces to 31 and the right side also reduces to 31. The graph shows every valid pair. Its empty spaces are pairs that fail the equation.

To see where the addition shapes come from, imagine complex numbers y + ix on the unit circle. Multiplying two gives imaginary part x₁y₂ + x₂y₁ and real part y₁y₂ − x₁x₂. That is an analogy for the two mixed products. On our curve the coefficient of x² is −1, which changes the second numerator’s sign. The quartic term dcurvex²y² introduces opposite correction factors in the denominators. For Edwards curves with square −1 and nonsquare dcurve over an odd prime field, this law gives a valid sum for every pair of curve points, including equal and opposite points. RFC 8032 §3

t = dcurvex₁x₂y₁y₂ mod p x₃ = (x₁y₂ + x₂y₁) · (1 + t)⁻¹ mod p y₃ = (y₁y₂ + x₁x₂) · (1 − t)⁻¹ mod p

The subscripts 1 and 2 name the two input points, and 3 names their sum. All the products and inverse calculations here concern coordinates, so every one uses 53. Multiplication by a denominator’s inverse is field division. For B + B, t is 30, the reduced numerators are 26 and 10, and the denominators are 31 and 24. Their inverses are 12 and 42 because 31·12 ≡ 24·42 ≡ 1 (mod 53). The sum is (47, 49). Coordinate-wise doubling would give (8, 33), which fails the curve equation.

The identity is I = (0, 1). Substitute it as the second input and both denominators become 1, so the formulas return the first point. The inverse of (x, y) is (−x mod p, y). Adding the inverse cancels the x numerator and gives y = 1 by the curve equation. Here the neutral point has ordinary coordinates.

Calculation · Find −B and check its sum

−4 mod 53 = 49, so −B = (49, 43). Try [1]B + [6]B in the lab. This returns (0, 1).

Deeper intuition · What motivates those numerators?

Start with the simpler equation y² − x² = 1, which sets the quartic coefficient to zero. In that case (y + x)(y − x) = 1. For two inputs, multiply their two y + x factors together and their two y − x factors together. The resulting factors still multiply to 1. Expanding gives a sum and difference of exactly the same numerators in the Edwards formulas. The quartic term changes the curve, and the opposite denominators adjust this multiplication rule to give the Edwards group law.

Chapter 3

Choose the modulus by asking what wraps

The coordinate grid repeats every 53. The sequence of multiples of B repeats every 7. These are different cycles.

Coordinates wrap modulo p

When reflecting (13, 12), replace 13 by −13 mod 53 = 40. Replacing it by −13 mod 7 = 1 gives (1, 12), which is off the curve.

Base-point counts wrap modulo L

[7]B = I so [13]B = [6]B. Using 53 as the period would let you replace j with j + 53 even though [53]B = [4]B.

L is the prime order of B, the first positive number of additions that returns to I. It has the same role as n in the ECDSA guide. Every multiple of B is in its seven-point subgroup. Any point in this subgroup is also unchanged if you add L to its multiplier. This is the reason you can reduce a signing scalar modulo L. For a point outside that subgroup you must first reason about its own order.

Calculation · Make [5]B with double-and-add

Write 5 = 4 + 1. Double B to get (47, 49). Double that to get (40, 12). Add B once to obtain (6, 49). Point multiplication needs a number of additions proportional to the number of bits in the scalar when computed this way.

Chapter 4

Where the two secret scalars come from

A signature needs a long-lived signing scalar and a temporary nonce scalar. Ed25519 derives both from one secret seed, through separate paths.

Start with 32 bytes from a cryptographically secure random generator. SHA-512 expands that seed to 64 bytes. In the first half, clear the three lowest bits and bit 255, and set bit 254. Interpret these modified bytes as a little-endian integer a. This bit operation is called pruning or clamping. It makes the integer a multiple of 8 and sets its most significant 1 at bit 254. These are key derivation rules, separate from scalar reduction. The second half remains a secret byte string called the prefix.

First 32 / last 32 bytesPrune to a / keep prefix

Use the scalar a to compute A = [a]B. Publish the encoding of point A and keep the seed, a, and prefix secret. The toy example starts after seed expansion with a chosen a = 5, so A = (6, 49). The actual clamped integer in Ed25519 is larger than L, and its residue acts identically on B because [L]B = I.

Detail · What puts A in the signing subgroup?

A is a multiple of B, so [L]A = [a]([L]B) = [a]I = I. This follows from the choice of base point. Clamping imposes a fixed bit length and a multiple of 8 on the integer before that multiplication. It does not validate received points.

For pure Ed25519, the nonce scalar is r = LE(SHA-512(prefix || M)) mod L. Here M is the exact message byte sequence, || concatenates bytes, and LE reads the digest as a little-endian integer. The prefix keeps nonce derivation secret even when the message is public. Distinct messages normally produce distinct nonces on the real curve. The same seed and same exact message produce the same nonce and signature. For the toy walk, take r = 3 as an illustrative reduced nonce, giving R = [3]B = (13, 12). RFC 8032 §§5.1.5–5.1.6

Application · Why keep the prefix private?

Anyone with the prefix and a signed message can repeat the nonce derivation. Knowing one nonce and its public challenge can expose the signing scalar, as Chapter 9 shows.

Chapter 5

Build a signature Bob can check

Alice can combine secrets as integers. Bob can combine their public counterparts as points. The signature makes those two calculations meet.

Bob knows the base point B and the public key A = [a]B. Alice sends the nonce point R = [r]B, so Bob can add it to a public multiple of A. Choose that multiplier by hashing what the signature is meant to bind together: the encoded R, the encoded A, and the message bytes M, in that order.

c = LE(SHA-512(enc(R) || enc(A) || M)) mod L

c is the public challenge (called k in RFC 8032). Tying it to the message makes the equation change when the message changes. Tying it to R means you have committed to the point before you know the challenge. Hashing A also binds the challenge to the exact public-key bytes. In the toy record, use c = 2 as an illustrative hash residue.

Bob could form R + [c]A. Alice wants to give him a number S with [S]B equal to exactly that point. Because Alice knows the two counts r and a that Bob can only see as points, she can add those counts:

R + [c]A = [r]B + [c]([a]B) = [r + ca]B S = (r + ca) mod L = (3 + 2·5) mod 7 = 6

The sum 13 and its residue 6 give the same point because their difference is 7, one full cycle of B. The toy signature is ((13, 12), 6), written as R and S. The inputs a and r stay private, while the curve, message, challenge, public key and signature are public.

Intuition · Why does R belong in the challenge?

Imagine the challenge were fixed before R was chosen. Someone could pick S, then compute R = [S]B − [c]A using public points. Hashing R into c makes that construction circular. Changing R requires recomputing c.

Calculation · Why skip inversion when verifying?

[S]B = [r + ca]B because the difference between the two counts is a multiple of L. Distribute point multiplication over addition and substitute R = [r]B and A = [a]B to get [S]B = R + [c]A. No scalar inverse is needed to isolate R or S for this comparison. The affine Edwards point law still uses field inverses.

Edge case · What if c is zero?

[0]A is the identity, so that individual equation reduces to [S]B = R. The toy lets you pick zero on demand. For a fixed set of inputs on the real curve, a hash behaving like a uniform random source gives a zero residue with probability about 1/L.

Chapter 7

Read points and scalars from bytes

Given the Y-coordinate, the Edwards equation usually gives two candidate X-coordinates. One parity bit selects the intended one.

Gather the terms containing x² to obtain y² − 1 ≡ x²(1 + dcurvey²) (mod p). Divide by the field denominator to get x² ≡ (y² − 1)(1 + dcurvey²)⁻¹ (mod p). At R’s y = 12, the numerator is 37 and the denominator is 9, whose inverse is 6 modulo 53. Thus x² = 10 modulo 53. Both 13² and 40² reduce to 10. The canonical representatives x = 13 and x = 40 have opposite parity because 53 is odd.

Point decompression lab

Start with the nonce point’s y = 12. Flip the parity bit to get its inverse.

(13, 12)

x² = 10 mod 53. Roots are 13 and 40. The odd root is 13.

In Ed25519, write the canonical Y-coordinate as 32 little-endian bytes. Since p < 2²⁵⁵, the most significant bit of the last byte is free. Put x mod 2 there. This bit is part of the encoding of an individual point. The public key encodes A this way and the signature encodes R this way.

Bytes 0–31enc(R)Y little-endian, X parity in bit 255
Bytes 32–63LE₃₂(S)Canonical scalar, little-endian

Little-endian puts the least significant byte first. For a short illustration, the integer 0x1234 occupies bytes 34 12, followed by zero padding if you need 32 bytes. The verifier rejects encoded Y values ≥ p, square-root failures, and x = 0 paired with parity 1. It rejects S ≥ L instead of reducing the received bytes. Reducing them would give multiple encodings of the same response, such as S and S + L. RFC 8032 §§5.1.2–5.1.3, 5.1.7

Ed25519 has no ECDSA-style Low-S normalization. Replacing S with L − S negates the left side of the equation, and negating R also changes the challenge input. Likewise, the X-parity bit helps reconstruct R itself. It is unrelated to Ethereum’s recovery metadata, and the usual Ed25519 verification procedure takes A as an input. Because c hashes A, even an attempt to rearrange the equation for A depends on already having its bytes.

Experiment · What happens at y = 1?

Set y to 1. The only root is x = 0. Parity 0 decodes to I = (0, 1). Parity 1 is invalid because x = 0 has no second representative in the field’s canonical range.

Implementation detail · How can you find a square root in the real field?

Checking every possible X works for the toy field. The real prime is 5 modulo 8, which gives a faster rule. Write v for the value of x² you already computed. Try x = v(p+3)/8 mod p, using modular exponentiation. If x² = −v modulo p, multiplying x by a square root of −1 changes its square to v. After confirming x² = v, choose the root with the encoded parity. A candidate that fails the square check cannot decode to a curve point. RFC 8032 §5.1.3

Chapter 8

Why might a verifier multiply both sides by 8?

The proof used points generated from B. Decoding a point proves it is on the curve. Subgroup membership is a separate question.

The full group has order 8L. Any curve point P satisfies [8L]P = I. Multiply it by 8 and the result is killed by L, since [L]([8]P) = [8L]P = I. In particular, a point T of order 8 has [8]T = I. Our toy curve has such a point at (1, 23). Doubling it twice gives [4]T = (0, 52), and one more doubling gives the identity.

The RFC 8032 check multiplies both sides by 8, as below. It also permits the stricter check without the factor of 8. For honestly generated keys and signatures both comparisons agree. For arbitrary decoded points, the cofactored check accepts an equality up to a difference killed by 8. Since 8 is invertible modulo odd L, multiplying by 8 is reversible within the prime-order subgroup and preserves differences there. RFC 8032 §5.1.7

Application · Why does the order-7 difference survive?

[8]B = [1]B because seven additions complete a cycle. That result is B, so it still separates the two points.

Chapter 9

Why checking is easier than signing

Bob can answer “did these two points match?” efficiently. Producing a response to an already fixed challenge would require a different calculation.

Suppose someone picks a nonce, publishes its point R, and computes c for Alice’s public key and a message. They can now form R + [c]A. Alice has the secret a and can compute the response directly. An outsider following this route would have to find the count S that reaches the target point from B. Given only the point, finding that count is the elliptic curve discrete logarithm problem. The toy table makes it easy. On the real curve, the order is about 2²⁵² and a generic classical discrete-log search takes on the order of 2¹²⁶ group operations.

Could an outsider choose S first and solve for R? For a fixed c this rearrangement works, but the actual c is a hash of R, A, and the message. The computed point would have to hash back to the guessed challenge. These routes explain the difficulty of making the equation hold without a secret. They are intuition for the security of the construction. The practical guarantee also depends on secure hashes, key handling, and the protocol’s validation rules.

One disclosed nonce

If someone learns r and the challenge is nonzero modulo L, subtract r from S and multiply by c⁻¹. On the toy record, 6 − 3 = 3 and 2⁻¹ = 4 mod 7. The recovered residue is 3·4 mod 7 = 5. An attacker needs only this residue to act as the signer, even if it gives them neither the original seed nor the secret prefix.

One nonce across two different challenges

Imagine a faulty signer reuses r = 3 on a second message whose illustrative challenge is c₂ = 4. Then S₂ = (3 + 4·5) mod 7 = 2. Both signatures have the same R. Subtract their response equations and r cancels:

S₁ − S₂ ≡ (c₁ − c₂)a (mod 7) 4 ≡ (2 − 4)a ≡ 5a (mod 7) a ≡ 4·5⁻¹ ≡ 4·3 ≡ 5 (mod 7)

Different challenges must differ modulo L for the inverse to exist. Signing the same bytes again gives the same challenge and response, so the subtraction yields only 0 ≡ 0. Deterministic derivation avoids a fresh random draw for each signature. It still relies on a well-generated seed and protection against side channels, faults, and leakage of the prefix. RFC 8032 §8

Know what your protocol calls Ed25519

Pure Ed25519
The variant traced here. It hashes the exact message bytes in the nonce and challenge computations. Application rules still determine how to serialize the object before signing it.
Ed25519ctx
Adds a domain-separation prefix that includes a context string to both hashes. The context distinguishes protocol uses. Even an empty context here uses that prefix.
Ed25519ph
Prehashes the message with SHA-512 and uses a domain-separation prefix with a different mode flag. Giving SHA-512(message) as the input to pure Ed25519 produces a different construction.
Ed448
Another EdDSA instance. It uses a different curve, hash and byte format.
X25519
A Diffie–Hellman key-agreement function on the related Montgomery curve. Its 32-byte public keys encode a Montgomery u-coordinate. Ed25519 signs and uses compressed Edwards points. Key sizes alone tell you little about compatibility.
Bitcoin’s BIP340
Also checks a Schnorr-style equation, but on secp256k1, with its own point encodings, hash rules, and nonce derivation. The related equations do not make the algorithms interchangeable.

For application examples, SSH identifies this signature algorithm as ssh-ed25519 and wraps the raw signature in SSH fields. X.509 uses algorithm identifiers and containers to distinguish Ed25519 and X25519 keys. A file or library may use “private key” for a seed, a seed with its public key, or a serialized key container. Check which representation your interface expects. RFC 8709 · RFC 8410

Application · A 64-byte value arrives. Is it a signature?

Length alone cannot tell you. It could be a raw signature, a 64-byte hash, or a key representation. The protocol identifies the field and the algorithm. For an Ed25519 signature, the first half decodes as a point and the second as a canonical response scalar.

Capstone

Work through one signature from memory

Use the same toy curve with a = 5 and r = 3. Assume the challenge for the chosen message is c = 2. Use the subgroup table to check your point additions.

  1. Compute A and R. Explain which parts of these calculations use modulo 53.
  2. Find S. Explain why you can remove a full cycle of seven from the count.
  3. Use only the public inputs to compute and compare both verification points.
  4. Write the toy Y-coordinate and parity bit for R. Explain what point a flipped bit would decode to.
  5. Keep the signature and change c to 4. Find which side of the verification equation moves.
  6. Suppose the signer instead creates a second signature with c = 4 and uses r = 3 again. Show how to recover the secret residue without knowing the nonce.
Hint

Write every point as a multiple of B first to predict the answer. Then look up its coordinates or compute directly with the addition formula. For the last step, write both response equations before subtracting them.

Worked answers

A = [5]B = (6, 49) and R = [3]B = (13, 12). Coordinate additions and inverses wrap modulo 53. S = 13 mod 7 = 6. The left path reaches [6]B and the right takes [3]B + [2]A = [3]B + [3]B, also [6]B = (49, 43). The point encoding uses y = 12 and odd parity. A flipped bit decodes to (40, 12). Changing the challenge to 4 moves only the right side to [2]B. If the nonce is reused, the second response is S₂ = 2. Subtraction gives 6 − 2 ≡ (2 − 4)a, so 4 ≡ 5a (mod 7) and a = 5.
