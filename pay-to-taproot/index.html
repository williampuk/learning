One output, two ways to spend

A P2TR output is native SegWit version 1 with a 32-byte witness program. That program is x(Q), the x coordinate of the output public key. A spend chooses between a signature for that key and a script revealed with a Merkle proof.

Key path

Schnorr signature

Bitcoin checks the signature against x(Q). The witness reveals neither the internal key nor whether any scripts were committed. A wallet that knows the internal secret can adjust it by the tweak, with BIP 340’s parity handling.

Script path

stack inputs…scriptcontrol block

Bitcoin reconstructs Q to check the commitment, then applies the rules for the leaf version. For Tapscript, that includes executing the revealed script. Sibling hashes can reveal the depth, while other scripts stay undisclosed unless exposed elsewhere or guessed.

Witness diagrams omit the optional annex. When at least two witness items are present and the last begins with 50, Bitcoin removes that item before choosing the path. The annex is covered by the signature hash.

From the wallet’s inputs to the address

P = lift_x(internal_key)
t = int_be(HTapTweak(x(P) ‖ m))
Q = P + t · G
scriptPubKey = 51 ‖ 20 ‖ x(Q)
internal_key, P
The creator chooses a 32-byte x-only public key, for example the x coordinate of a wallet public key or a properly aggregated key. lift_x finds the secp256k1 point at that x coordinate with even y. The two possible y coordinates have opposite parity.
m, Htag, ‖
m is the tree’s 32-byte Merkle root. With no tree it is the empty byte string. H is tagged SHA-256, defined below. The symbol ‖ joins byte strings end to end.
t, G, Q
int_be reads the hash as an unsigned big-endian integer t. G is the fixed secp256k1 generator point. Scalar multiplication t · G and point addition move P to Q. Bitcoin rejects a tweak at least the curve order n or a result at infinity. The order is the number of multiples of G before the group cycles.
51, 20, x(Q)
Hex byte 51 is OP_1, the version marker. 20 pushes 32 bytes. x(Q) is those bytes, padded big-endian. The mainnet address uses bc, witness version 1, the program converted to 5-bit groups, and a Bech32m checksum.
How an x coordinate becomes a curve point
y² ≡ x³ + 7 (mod p),   p = 2²⁵⁶ − 2³² − 977
y₀ = (x³ + 7)(p + 1)/4 mod p

p is the fixed field prime of secp256k1. Read the 32 public-key bytes as an integer x. First check x < p and that the candidate y₀ satisfies the curve equation. Then pick the even value from y₀ and −y₀ mod p. This gives the internal point P. The tweaked point Q can have either parity, which is why the control block carries that bit.

How the leaf and branch hashes are made
Htag(data) = SHA256(SHA256(tag) ‖ SHA256(tag) ‖ data)
L = HTapLeaf(v ‖ CompactSize(len(s)) ‖ s)
Branch(a, b) = HTapBranch(min(a, b) ‖ max(a, b))

The tags are ASCII strings Bitcoin defines to give each kind of hash its own domain. v is the leaf version byte, normally hex c0 for Tapscript. s is the exact serialized script. Its size in bytes uses Bitcoin’s CompactSize integer encoding. For OP_1, the script is 51 and its length is 01, so the hash input after the tag prefix is c00151.

a and b are 32-byte child hashes. Compare them byte by byte, then put the smaller one first. Swapping siblings keeps the hash. Changing which children are paired can change the root. In the default tree, m = Branch(Lₐ, Branch(Lᵦ, L𝒸)), where Lₐ, Lᵦ, and L𝒸 are the hashes of leaves A, B, and C. A single leaf is its own root.

In that default tree, a proof for B carries L𝒸 first and Lₐ second. Start with B’s leaf hash, combine with C’s hash, then combine that result with A’s. Each step sorts its two inputs, so the proof never needs left or right indicators.

Verify one revealed script

Take x(Q) from the previous output being spent, then take the script and control block from the spending input’s witness. The verifier checks their commitment against that previous output. Signatures, script execution, and transaction validity are outside this check.

Header1 byte · leaf version and Q parity
x(P)32 bytes · internal key
h₁ ‖ … ‖ hd32 bytes per sibling · nearest first

The header’s low bit is y(Q) mod 2. Mask it off with & fe to obtain the leaf version. The control block is 33 + 32d bytes, where d is the number of siblings from the leaf to the root (0–128). A single leaf has a 33-byte control block.
